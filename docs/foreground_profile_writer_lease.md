# STEP 64: foreground profile writer exclusion at startup

Implementation supplied; target Dart/Flutter tests pending. This is a startup prerequisite, not a completed transfer release. No public flags enabled or server deployed.

Before StorageService.init, account language persistence, notifications, Signal initialization or foreground login, acquire a process-lifetime lease for the canonical application-support directory. Use an exclusive loopback ServerSocket bind (same-process isolate and process exclusion) plus a non-blocking advisory lock on a stable profile lock file. Canonicalize symlinks and Windows path case for port derivation. Never delete/replace the lock file: a stale file is harmless; OS-held resources determine ownership. Crash/process termination releases the resources; close is idempotent. No credentials, keys or user data are stored in the lock file or sent over the socket. Accepted socket clients are immediately destroyed.

If acquisition fails (including unrelated port collision, filesystem permission error or another writer), stop before opening app storage and show a plain RU/UK/EN startup message using the OS language. No silent second writer. A port collision can deny startup, not grant a second lease. The lease is for one canonical application profile, across accounts; separate directory profiles are not a supported way to share the same secure-storage namespace.

Important limits: this wraps the foreground main entry point only. Background Firebase/headless engines, native helper programs, updater handoffs and other entry points are not claimed covered. Old released binaries that do not cooperate can still write the profile; close old copies before testing a new build. Secure-storage/profile namespace equivalence for alternate installers must be verified on Windows/Android. Advisory file locks do not stop hostile processes modifying storage. This does not replace native platform access control or prove that every app data writer acquires a lease. Do not enable transfer based solely on this step.

Tests supplied use temporary profiles and actual Dart subprocesses: same-process exclusion, cross-process exclusion both directions, orderly release, crash release with stable file retained and idempotent close. The test-only probe imports the exact production lease module and receives no real app profile. Native transfer/Signal/retired-session regressions and server tests remain included. Main startup integration receives analyzer validation; real Android/Windows launch, second-copy UI, updater behavior and headless isolation still require platform verification. No working build is installed/launched by this source-and-test step.

Remaining: explicit retired-key receive UI/grace policy, cancellation/delivery caching, headless writer audit, real full-transfer device tests, old/new history/state transfer and release audit. Real keys/contacts/history, site/GitHub/public packages and running server are unchanged.
