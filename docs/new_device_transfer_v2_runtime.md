# STEP 60: isolated new-device v2 runtime

Status: protocol implementation supplied; native Flutter checks pending. Public UI flag remains OFF. No release or complete history migration is claimed.

The new runtime stages/resumes the STEP 59 sealed private candidate, uses only explicit password-checked v2 prepare/status/activation modes, verifies both native Signal proof domains against the direct old-device pin, persists the proof before commit and the current receipt before installing the exact candidate. It checks username/account UUID/activation epoch in login_success and requires e2ee_bundle_published.ok before reporting protocol-ready. It never falls back to ordinary login, stores passwords in fields/journals, overwrites an unrelated active key or deletes candidates on transport failure.

A lost commit response is resolved through a fresh password-checked status login for the same key/nonce. A definitive negative status can reset only a verified proof; the private key remains the same. A new client instance then prepares a new request. Committed/installed states cannot be reset from negative status. Every async continuation checks the current operation; cancelling closes transport and retains recovery state.

TLS is required except loopback test endpoints. Frame size and response duration are bounded. Unknown/out-of-order frames fail closed. Error details from private storage or credentials are not surfaced by this controller. A fake wire is injectable for deterministic native tests; production uses WebSocketChannel.

Important integration boundary: this isolated controller is NOT connected to NewDeviceTransferScreen/AuthScreen/SocketService in this step. Protocol-ready means activation and durable bundle publication were acknowledged on its isolated channel, not that the chat client adopted the authenticated channel. The current UI continues using v1 behind a default-OFF development flag. Do not enable the UI or run this controller against real accounts until authenticated channel handoff/initial inbound queue preservation is implemented and audited: activation may deliver initial chat events, and closing an isolated authenticated channel is not a production handoff. Unknown frames therefore stop rather than silently discard chat traffic. The old-device send/ACK UX, contact certificate routing, stale-directory/freshness policy, late old-session ciphertext, history migration and real two-device Android/Windows tests remain pending. Enforce a single local profile writer before enablement, as documented in STEP 59.

Tests cover protocol ordering, Native Signal proofs, mismatch rejection, uncertain-commit recovery, negative publication ACK, stale status, unchanged candidate across retries, protected existing identity, endpoint restrictions and cancellation. Secure storage is mocked; real keys/contacts/history are not touched. They do not prove real TCP/server bootstrap behavior or end-to-end UI operation. Existing 48 targeted tests run as regressions. Production server/source, website, GitHub and public packages are unchanged.
