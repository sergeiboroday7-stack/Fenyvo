# Fenyvo

Fenyvo — кроссплатформенный мессенджер для Android и Windows с личными и групповыми чатами, аудио- и видеозвонками, медиа, уведомлениями и функциями приватности.

## Мой Fenyvo

Вкладка настроек постепенно превращается в собственный личный кабинет Fenyvo.
Первый этап добавляет фирменную карточку профиля и быстрые переходы к профилю,
QR-контакту, оформлению и защите. Телефон и дата рождения являются
необязательными: пользователь вводит их самостоятельно и отдельно разрешает
показ другим аккаунтам.

## Публичный сайт

Исходники статической страницы находятся в `website/`. APK и файл его
контрольной суммы являются артефактами релиза и не добавляются в Git. Перед
публикацией APK собирается с публичным адресом сервера:

```text
--dart-define=SPARTAN_SERVER_URL=wss://fenyvo.com/ws
```

Страница адаптирована для телефона и компьютера и содержит описание Fenyvo,
инструкции по установке, номера сборок, размеры и проверяемые суммы SHA-256.
Главная и юридические страницы локализованы на русский, украинский и английский
языки. Выбор языка определяется браузером и может быть изменён вручную.

## Групповые видеозвонки

Групповой звонок поддерживает отдельные роли владельца, ведущего, модератора, участников сцены и зрителей.

Зрители могут оставаться в групповом чате и отправлять запрос на выход на сцену. Ведущий или модератор может принять или отклонить запрос.

При временной потере ведущего его роль не должна автоматически передаваться случайному участнику. Возврат владельца восстанавливает его полномочия.

## Личные звонки

Fenyvo поддерживает личные аудио- и видеозвонки.

Во время видеозвонка удалённое видео занимает основной экран, а локальная камера отображается в компактном окне.

На Android поддерживается громкая связь. На Windows используется системное аудиоустройство, включая подключённую гарнитуру.

Во время исходящего вызова воспроизводится отдельный фирменный двухнотный сигнал
ожидания. Для занятого абонента и завершения разговора используются разные
короткие сигналы. Экран звонка
предупреждает о слабом соединении и показывает восстановление после краткого
обрыва. В личной переписке локально отображаются входящие, исходящие,
пропущенные и отклонённые вызовы с длительностью состоявшихся разговоров.
WebRTC автоматически адаптирует медиапоток к доступной пропускной способности.
Для сетей, блокирующих прямое соединение через STUN, требуется отдельный
TURN-сервер; публичные TURN-учётные данные в исходный код не добавляются.

## Безопасность

Секретные и локальные данные не публикуются в Git.

В репозиторий не должны попадать:

- `.env`;
- Firebase Admin credentials;
- приватные ключи;
- Android signing keystore;
- `android/key.properties`;
- локальные базы;
- пользовательские медиа;
- FCM-токены;
- диагностические файлы;
- SDK, NDK и build-кеши.

Android release подписывается постоянным release-ключом Fenyvo. Сам ключ и пароль не публикуются.

## Сервер

Серверная часть работает на Node.js.

Запуск:

```text
node server.js
```

Установка зависимостей:

```text
npm ci
```

Настройки берутся из переменных окружения или локального `.env`. Безопасный шаблон находится в `.env.example`.

В рабочем размещении Node.js доступен только на loopback-интерфейсе, а внешний
HTTPS/WSS-трафик принимает nginx:

```text
127.0.0.1:8080
```

Публичный адрес:

```text
wss://fenyvo.com/ws
```

Конкретные домашние или локальные IP-адреса разработчика в документации не публикуются.

`SPARTAN_SERVER_URL` пока остаётся внутренним техническим именем параметра сборки.

```text
flutter build windows --release
```

Результат:

```text

```

Публичный ZIP содержит `Install-Fenyvo.cmd` и ASCII-совместимый PowerShell-

обновляет ярлыки рабочего стола и меню «Пуск».

## Публичное размещение и защита

Fenyvo опубликован на `fenyvo.com`. WebSocket и медиа-сервис привязаны к
`127.0.0.1`; nginx является единой внешней точкой входа. На уровне nginx и
Node.js действуют ограничения соединений, частоты сообщений, размера payload и
параллельных загрузок. SSH использует ключи, UFW и fail2ban активны. Шаблоны в
`deploy/security/` не содержат TURN-секрет, Firebase credentials или ключи.

Это снижает риск злоупотреблений, но не означает абсолютную защиту от объёмного
DDoS: для него дополнительно нужен внешний фильтрующий прокси, совместимый с
WebSocket, а TURN требует отдельной сетевой стратегии.
