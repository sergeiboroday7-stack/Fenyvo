## 2026-10-15 — GROUP CALL STABILITY / 1.8.2+4237

- Исправлена гонка при переходе из просмотра группового звонка на сцену: уже
  одобренный участник больше не отклоняется, если запрос подключения пришёл
  раньше команды выхода из режима зрителя.
- Ранние WebRTC SDP/ICE-сигналы теперь ожидают полной готовности соединения и
  не теряются во время одновременного подключения нескольких участников.
- Устаревший снимок состояния больше не выкидывает ведущего или участника из
  уже созданной новой сессии звонка.
- Групповые звонки используют выдаваемые сервером временные TURN-реквизиты с
  сохранением STUN как запасного варианта; секрет TURN в приложение не
  встраивается.
- Добавлен регрессионный серверный сценарий для опережающего подключения;
  локально прошли 28 из 28 Node-тестов. Flutter-анализ, сборка APK и проверка
  реального звонка на нескольких телефонах отмечены как ожидающие выполнения.

## 2026-10-12 — SERVER SECURITY HARDENING, PHASES 1–2

- Node/WebSocket и медиа-сервис переведены с публичных интерфейсов на
  `127.0.0.1`; внешний доступ проходит только через nginx. TURN оставлен на
  необходимых публичных TCP/UDP-портах.
- SSH переведён на вход по ключу, отключены парольный вход, X11 forwarding и
  избыточное число попыток. Fail2ban, UFW и все рабочие службы сохранены.
- Добавлены nginx-лимиты запросов и соединений, безопасные таймауты и заголовки,
  16-МБ предел одного WebSocket-сообщения и системные ограничения службы.
- nginx теперь перезаписывает `X-Forwarded-For` фактическим адресом соединения,
  поэтому клиент не может подделать IP для серверных ограничений.
- Добавлены лимиты WebSocket: до 50 соединений с одного адреса, до 900 сообщений
  в минуту на соединение и до 3000 сообщений в минуту на адрес.
- Одновременные медиа-загрузки ограничены восемью на сервер и двумя на
  пользователя; сервер сохраняет резерв 2 ГиБ свободного диска и удаляет
  оборванные частичные файлы.
- Обе публикации выполнялись с резервными копиями и автоматическим откатом.
  Проверены синтаксис Node/nginx, HTTPS, WebSocket handshake, loopback-привязка,
  активность Fenyvo/nginx/SSH/coturn/fail2ban и фактическое отклонение 51-го
  тестового WebSocket-соединения. Полная защита от сетевого DDoS не заявляется;
  для неё ещё требуется отдельная прокси-архитектура с учётом TURN.

## 2026-09-09 — SPARTAN TRUST server enforcement

- Сервер проверяет блокировку до отправки личного сообщения, статуса печати,
